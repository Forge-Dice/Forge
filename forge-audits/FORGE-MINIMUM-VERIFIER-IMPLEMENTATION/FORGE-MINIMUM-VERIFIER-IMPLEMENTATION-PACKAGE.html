3. Git Object Model

NORMATIVE — Git ist Transport und geprüfter Objektspeicher, nicht Semantik-Orakel für Scope. Objektidentitäten sind 20 rohe Bytes / 40 Lowercase-Hex; Dateipfade bleiben vom Roh-Tree bis zum Change-Set bytes. Ausgabe darf erst nach vollständiger Pfadprüfung in ASCII erfolgen. OIDs sind Identitäten in der SHA-1-Repositorywelt; Git-SHA-1 ist hier kein Ersatz für den zusätzlichen SHA-256-Manifest oder gegen kompromittiertes GitHub gerichteter Integritätsbeweis.

  • Leere Testdatei, fehlendes Modul, Collection-/Suite-/Hook-/Unhandled-Error, unbekannter Status, pending, aborted oder partieller Report: keine vollständige Verifikation. Ein absent/todo/skipped-Test kann nicht durch zusätzliche Tests kompensiert werden.

Test-Titel aus Produktionsdaten können dynamisch wechseln: dann ist Inventory-Änderung bewusst ein Review-/Fehlerfall, keine automatische Aliasbildung.

Race-Limit: Die API bietet keinen atomaren Snapshot über PR, refs, reviews, Workflow und Settings. Wer eine atomare Freigabe gegen nachträgliche Policy-/Reviewänderungen verlangt, erhält NO-GO für diesen minimalen Workflow.
